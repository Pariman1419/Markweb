# Deploy Mark Web to 10.153.90.17 — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax. Steps marked **[USER]** wait for the user. Do not tick them yourself.

**Goal:** the API, web and auto-review worker run on `10.153.90.17` (Windows + Docker Desktop) on a free port, so Airflow `10.151.28.3` can call the scan API and the worker checks ELRs from the NAS without the dev PC.

**Architecture:**
- **.17 can clone from GitHub [user 2026-11-06].** The user clones `phase2/trial` on .17 and builds the images there with `docker compose build`, the same way Jenkins does on the dev PC. The preflight script checks that the build's downloads (PyPI, npm, Docker Hub, Oracle Instant Client) are reachable before building.
- **Worker becomes a compose service** using the same image as the API, behind compose profile `worker`, so Jenkins' dev deploy does not start it. The NAS share `//th1srnas03/ELR` is mounted read-only into the worker as a CIFS volume at `/mnt/elr`, so `NAS_ROOT=/mnt/elr/ADI` inside the container.
- **`docs_fp` must not depend on where the NAS is mounted**, otherwise every ELR looks "docs changed" the first time the worker runs on .17 (`\\th1srnas03\ELR\ADI\...` vs `/mnt/elr/ADI/...`).
- **Port:** any free port, chosen by a preflight script on .17 [user]. Not 8088 (NPIChecklist) or 8080 (Streamlit).
- **Out of scope:** Airflow Task 3–4 (Codex, `docs/superpowers/plans/2026-11-06-airflow-dags.md` on `phase2/airflow`) run after Task 5 here; WebSocket/web UI (spec §9 step 5); Jenkins deploy to .17 (deploys stay manual for now).

**Tech Stack:** Docker Desktop (Linux containers) on Windows, docker compose, git, PowerShell 5.1 for the .17 script, Python 3.12.

**Spec:** `docs/superpowers/specs/2026-11-05-auto-review-flow-design.md` §9 (deploy order), `services/README.md` "Phase 2 Trial Deployment (10.153.90.17)", memory note: dev PC is unreachable inbound from the server subnet, `.3 → .17` works.

## Global Constraints

- **No secrets in git or logs.** `.env` is copied to .17 by the user by hand; `.env.example` gets the new keys with empty values only.
- **Customer data** (`data/files`, ABS images, `work/`) never goes into git. `data/files` (13 MB) is copied to .17 by the user, internal only.
- **NAS is read-only:** the CIFS mount uses `ro`.
- **`mark_logic` stays insert-only; runs 1–19 untouched.** `scripts/check_trial_readonly.py --run 19` must still pass 8/8 after deploy.
- **Never stop vLLM on the A100.** The worker only calls `10.151.28.9:50051`.
- **One live worker.** After .17 is up, the dev PC must not run `services/worker/main.py` or the `worker` profile against the real queue.
- **Process:** every commit updates HANDOFF §4 and `docs/qa/QA_LOG.md`; a task is done only after push and a green Jenkins build.

## Review Focus

1. **NAS mount fails or is empty on .17** (wrong credentials, SMB version) → the worker must fail loudly at start, not resolve every ELR as `HOLD:ABS_NOT_FOUND`. Test in Task 3.
2. **Same ELR, same files, different mount root** → same `docs_fp`. Test in Task 2.
3. **Chosen port is free now but held by a stopped Docker container or reserved by Windows (excluded port range)** → preflight must treat those as busy. Test in Task 4.
4. **Deploying from a checkout that is dirty or not at `origin/phase2/trial`** → preflight FAILs and names the problem. Test in Task 4.
5. **Airflow cannot reach the port because Windows Firewall on .17 blocks it** → preflight prints the exact `New-NetFirewallRule` command; Task 5 checks from `.3`.
